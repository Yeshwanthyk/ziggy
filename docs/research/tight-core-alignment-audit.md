# Tight-core alignment audit

2026-09-29. Review of the current implementation, not authorization to rewrite it.

**Recommendation: tighten the existing Bun/TypeScript/Effect core, keeping Pi.** The strongest findings concern resource ownership, a few concrete boundary defects, and overlapping contracts. They do not justify replacing the agent loop or changing languages. Most of the primitives already use schemas, typed errors, scoped resources, and plain total calculations appropriately.

The useful target is a core with fewer independent ownership rules and fewer names for the same capability. File count and line count are secondary measures. Preserve the Profile's visible files, Pi's session authority, extension admission and rollback, memory isolation, and the existing client-facing behavior.

## Fix the authority defects first

Priority here means recommended work order. A demonstrated failure branch is distinguished from an observed production incident.

### A01 — Retain session writer ownership until shutdown is known to have finished

**Highest priority; reproduced correctness defect.** [openChat](/Users/yesh/code/personal/ziggy/src/adapters/pi/pi-agent.ts:1192) releases its writer lease on every construction failure, including failed activation rollback. Its [dispose path](/Users/yesh/code/personal/ziggy/src/adapters/pi/pi-agent.ts:1203) also releases the writer unconditionally through `ensuring`, even when Pi disposal rejects. Meanwhile [leaseProfileRuntime](/Users/yesh/code/personal/ziggy/src/adapters/pi/profile-runtime-lease.ts:68) deliberately retains the package lease when shutdown is uncertain. The two ownership rules disagree.

The existing injected-runtime failure fixture was adapted in a disposable Profile. Activation failed, runtime disposal rejected, `ProfileExtensionRollbackFailed` was returned, and another lease for the same session ID was successfully acquired. **Premature writer admission is proven. Continued writing or transcript corruption is not.**

Related paths to include in one invariant inventory:

- Ordinary chat build/close: `pi-agent.ts:1192,1203`.
- Live specialist close: `pi-agent.ts:1410`.
- Print mode: independent writer finalizer at `pi-agent.ts:271` and runtime-cleanup failure recovery at `:327`.
- Direct specialist: `pi-agent.ts:1508,1535` and child cleanup in `specialist.ts:407,433`.
- Reserved replacement-session leases in `session-lease.ts:270` must obey the same stop-before-release rule.

**Smallest correction:** one local lifecycle owner couples the runtime and its transcript lease. A failure before any runtime exists can release normally. Once shutdown is uncertain, poison the usable handle and retain its lease object until process exit, following the existing package-lease policy. Normal shutdown and successful cancellation cleanup still release. Preserve the current SQLite authority and typed rollback information.

**Effect reference:** [`ensuring` is unconditional](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/internal/effect.ts:3954). This is correct library behavior. A simple replacement with interruptible `tap(release)` introduces another gap; acquisition, stop, and ownership handoff need masked ordering. [`acquireRelease`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/internal/effect.ts:3882) guarantees finalizer registration, not successful external shutdown.

**Blast radius:** all agent entrypoints, registry close, automation result append, and extension activation rollback. A retained writer intentionally prevents retry until process exit when shutdown failed. **Proof required:** augment the rollback test at `test/adapters/pi/pi-agent.test.ts:1098`; assert second-writer refusal after rejected cleanup, normal release after pre-runtime failure, successful close, and cancellation. Cover each entrypoint without repeating every low-level SQLite test.

### A02 — Stop Profile listing from overwriting concurrent registration

**Reproduced correctness defect.** [listProfiles](/Users/yesh/code/personal/ziggy/src/application/profiles.ts:315) reads registry entries, performs asynchronous inspection, then rewrites the valid subset at `:348`. [registerProfile](/Users/yesh/code/personal/ziggy/src/application/profiles.ts:299) can append a new path during that interval. The stale pruning rewrite removes it.

A real-filesystem fixture inserted registration after listing's registry read and before its next read operation. The new path was present before pruning and absent afterward. This proves the interleaving; it is not multi-process stress evidence. External Profile folders remain intact, but their discovery index loses the path.

**Smallest correction:** prefer making listing read-only and ignoring stale entries in its result. If automatic pruning is a required behavior, serialize register/prune across processes using one narrow registry mutation lock. Atomic rename alone cannot prevent stale overwrites. Do not add another Profile identity database.

**Blast radius:** setup registration, CLI Profile listing, resident directory discovery. **Proof required:** preserve a registration inserted between snapshot and prune; preserve non-clobbering Profile initialization. Existing sequential pruning tests must change deliberately if listing becomes read-only.

### A03 — Apply physical-file checks to the memory lock artifact

**Reproduced filesystem-boundary defect.** [withMemoryLock](/Users/yesh/code/personal/ziggy/src/adapters/pi/memory-write-tool.ts:503) validates its directories but opens the final SQLite file with `create: true` and no no-follow protection. A pre-created `MEMORY.md.sqlite` symlink to an absent path outside the disposable Profile was accepted; SQLite created the outside file and the memory update succeeded.

This proves outside-Profile creation through the lock path. It does not establish arbitrary file corruption or an external attack route. The neighboring [extension lock](/Users/yesh/code/personal/ziggy/src/adapters/bun/profile-extension-lock.ts:134) already validates its artifact and uses no-follow SQLite flags.

**Smallest correction:** reuse that physical-file opening policy where its contract fits, or apply it locally. Include applicable SQLite sidecars. Retain the per-document lock identity and bounded acquisition wait; do not merge package-mutation and memory-document lock ownership.

**Blast radius:** `memory_write` read/apply/backup/publish transaction. **Proof required:** a symlinked lock artifact leaves the outside target and memory document untouched, ordinary concurrent additions both survive, interruption releases waiting connections. Existing directory-symlink tests do not cover this final artifact.

### A04 — Own a UI handle between acquisition and registry publication

**Reproduced failure-path defect; current Pi subscription is not observed throwing.** [getOrOpenUi](/Users/yesh/code/personal/ziggy/src/application/chat-registry.ts:591) obtains a handle, then calls `makeLiveEntry`. Subscription is explicitly adapted as a typed failure at `:234`. On that failure the registry deletes its Opening entry and fails its waiters, but never disposes the acquired handle. Scope cleanup cannot find it afterward.

A fake handle with a throwing subscription produced a failed registration and **zero disposal calls even after the registry scope closed**. This establishes the supported API failure branch; it is not evidence of frequent production Pi subscription failures.

**Smallest correction:** acquire/use/handoff ownership from successful open to Live publication. Dispose exactly once if publication fails. On cleanup failure retain an unavailable ownership marker and prevent a second owner, using the channel [openAlias path](/Users/yesh/code/personal/ziggy/src/application/chat-registry.ts:420) as a partial precedent. Settle the Opening Deferred with failure: retaining a pending Opening unchanged would leave callers waiting. Apply A01 first so cleanup does not free an uncertain writer.

**Blast radius:** UI opens, concurrent waiters, capacity accounting, registry teardown. **Proof required:** throwing subscription, one disposal, every waiter completed, retry allowed after successful cleanup, retry refused after failed cleanup. Keep the existing shared-open and disconnect behavior.

### A05 — Bound the parent projection of `agent_run`

**Confirmed specification mismatch.** The [specification](/Users/yesh/code/personal/ziggy/docs/research/minimal-ziggy-scout.md:19) requires bounded parent tool output plus nested usage and a child reference. [createAgentRunTool](/Users/yesh/code/personal/ziggy/src/adapters/pi/specialist.ts:898) copies the full child answer into both text and `details.result.answer`. Discussion already has a bounded projection.

**Smallest correction:** cap both parent copies with one Unicode-safe total helper. Preserve complete child JSONL, child reference, usage, and short-answer behavior. Preserve direct specialist result semantics; voice output needs its own contract and must not be silently truncated by this change.

**Blast radius:** parent tool context and tool-details consumers. **Proof required:** a fake runner returning a large Unicode answer; both parent copies bounded, metadata and usage unchanged. No provider request or new session format is needed.

### A06 — Read mutable directory state when the Effect executes

**Reproduced latent defect.** [branch](/Users/yesh/code/personal/ziggy/src/application/profile-runtime-directory.ts:68) reads its Map immediately, while `markAvailable` and `markUnavailable` mutate inside Effects. Constructing a read before removal returns the removed branch later; constructing it before registration remains a failure later. Both directions were reproduced.

Current production composition seeds initial branches; no production calls to the mutation methods were found. Do not describe this as a current resident outage.

**Smallest correction:** `Effect.suspend` around the lookup and result construction. Keep the private Map and its current owner. [`Effect.suspend`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/Effect.ts:1101) and [`Effect.sync`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/Effect.ts:1115) document the required evaluation timing.

**Blast radius:** dynamic resident branch availability. **Proof required:** construct before mutation, execute after mutation, and re-execute the same Effect. No new service or data migration is warranted.

## Tighten ownership and composition

### A07 — Give Pi-required Promise callbacks an explicit Effect owner

**Structural lifecycle work; no escaped-work incident proven.** [chat-runtime-binding](/Users/yesh/code/personal/ziggy/src/adapters/pi/chat-runtime-binding.ts:41), construction/replacement callbacks in `pi-agent.ts:302,1185,1404`, and specialist tools start separate Effect roots. Many are awaited; the specialist tools correctly forward Pi's abort signal. They are intentional interop, but the lifetime/context rule is spread across local exceptions to the only-main execution instruction.

**Correction shape:** one scoped Promise runner per actual session/child owner, passed to required SDK callbacks. Specify admission after close, in-flight work during shutdown, context propagation, and handoff from acquisition to the completed runtime. Keep application APIs Effect-shaped and Pi callbacks Promise-shaped. Avoid a global runtime.

[`FiberSet.makeRuntimePromise`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/FiberSet.ts:239) is a supported starting point: it requires a scope and tracks launched fibers. Merely capturing services with `runPromiseWith` does **not** attach work to its owner's lifetime; its implementation creates a root fiber. An owned runner also does **not** make Pi's uncancellable construction Promise cancellable. Retain the current wait-for-settlement and dispose-before-release logic.

**Blast radius:** runtime construction, lease reservation, replacement, specialist callbacks. **Proof required:** retained callback after owner closure is rejected; in-flight callback shutdown follows the writer-release invariant; supplied context is visible; pending SDK construction still settles safely. Implement after A01, as one seam rather than a mechanical search-and-replace.

### A08 — Invalidate disposable Pi preflight loaders

**Lifecycle hygiene; process-wide leak unproven.** [preflight](/Users/yesh/code/personal/ziggy/src/adapters/pi/profile-extension-preflight.ts:117) and [health inspection](/Users/yesh/code/personal/ziggy/src/adapters/pi/profile-extension-preflight.ts:249) remove temporary agent directories but do not invalidate returned extension runtimes. Production quarantine already [invalidates its discarded loader](/Users/yesh/code/personal/ziggy/src/adapters/pi/pi-agent.ts:488). Pi's `invalidate()` marks captured contexts stale and unsubscribes tracked event-bus handlers.

Discarded loader-local cycles may be garbage-collected, so omission alone does not prove a memory leak. The useful invariant is explicit disposal of acquired probe contexts.

**Smallest correction:** bracket every successfully created probe service, including the second healthy rebuild. Invalidate before removing its temporary storage. Preserve the original admission failure if cleanup also fails. Deal explicitly with a pending uncancellable creation Promise; a finalizer cannot clean an object that has not yet been handed back. [`acquireUseRelease`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/Effect.ts:6600) supplies the bracket, not the SDK's cancellation semantics.

**Blast radius:** extension admission/validation, doctor, extension health views. **Proof required:** injected service creation records invalidation on success, diagnostic failure and two-loader quarantine; interruption cannot strand a late returned loader. Preserve optional-package quarantine and fatal-core policy.

### A09 — Move existing capability contracts inward without adding layers

**Structure, not a demonstrated runtime failure.** [Memory](/Users/yesh/code/personal/ziggy/src/application/memory.ts:2) imports its capability service, read result, and error source from the filesystem implementation. The neighboring `ProfileStore` already demonstrates an application-owned port implemented by an adapter.

Move the existing memory port and read shape into an application-owned contract, keeping physical-path checks in `adapters/fs`. Deriving error types from that owned port remains valid; an extra hand-maintained error union is unnecessary. Retain the same service count and Markdown authority.

[ProfileDirectory](/Users/yesh/code/personal/ziggy/src/application/profile-directory.ts:71) separately performs registry I/O and physical Profile checks. Once A02 settles registry semantics, share the narrow file-access/inspection boundary through the existing Profile port or a small injected capability. Preserve its different unavailable/unknown policy, path-derived IDs, and collision handling. Do not casually replace lexical path identity with `realpath`, which would change UI references and pins.

**Blast radius:** composition, Memory, directory discovery, fake adapters in tests. **Proof required:** typecheck and existing memory/directory tests; one injected implementation can exercise the application without importing its filesystem adapter. No file-format or UI migration.

### A10 — Continue narrow command composition in the existing work

**Structural dependency reduction; no gateway connection claim.** [legacy dispatch](/Users/yesh/code/personal/ziggy/src/main.ts:810) still provides the entire [CliLayer](/Users/yesh/code/personal/ziggy/src/composition.ts:131), and its handler yields the full service set before choosing a command. Models already has a narrow layer; sessions is present in the preserved working tree; memory extraction has started.

[`Effect.provide`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/internal/layer.ts:8) builds its layer before running the command. Therefore remaining core commands have a wider construction dependency than their behavior requires. Building a gateway layer does not itself establish a network connection. Repeated references to the **same named layer** also do not imply duplicate instances: [memoization](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/Layer.ts:185) already handles that.

Continue the existing plan for memory, auth, Profile operations and agent execution. Keep the resident/gateway graph at its existing edge. Do not start a competing composition redesign or expand this audit into every CLI area.

**Blast radius:** command startup and dependency requirements, stdout/exit behavior. **Proof required:** command-specific layer acquisition counters or recording stubs, plus existing CLI behavior checks. Same output, exit code and Profile policy; unrelated resident capabilities should not be acquired for a memory read. Startup/RSS improvements remain unmeasured.

### D01 — Simplify the agent forwarding seam after choosing one public handle

**Design decision, not a prerequisite for correctness fixes.** [ZiggyAgentLive](/Users/yesh/code/personal/ziggy/src/application/agent.ts:177) forwards through PiAgent, and its open path passes through [runtimeSessionFromChat](/Users/yesh/code/personal/ziggy/src/adapters/pi/runtime.ts:34), which spreads the handle and adds `events`/`close` aliases. No separate lifecycle owner is introduced there. The explicit `SessionRuntime` abstraction currently has no independent consumer that requires a broad runtime framework.

Prefer one authored, client-neutral agent/handle contract. The Pi layer can implement that contract, preserving injection and the live `isIdle` getter. Remove redundant private forwarding/aliases if caller tracing confirms they are unnecessary. Keep public substitution contracts; do not infer the public API from every field the Pi implementation happens to return.

There is a local rule conflict to settle: the minimal specification explicitly diagrams application → PiAgent adapter, while newer architecture guidance asks for inward dependencies. This proposed consolidation reconciles those rules; it is not an Effect requirement. Preserve Pi print mode and every current entrypoint. A useful completion criterion is fewer independently edited signatures for adding one control, with existing gateways and UI still compiling unchanged.

Do not begin by splitting `pi-agent.ts` into many forwarding files. First make its acquisition/stop/lease contract singular. Then separate only responsibilities with distinct owners, such as resource admission and handle control; move code only when it removes repeated decisions or reduces a concrete change's reach.

### Guardrails worth keeping or adding

1. **One owner for every acquired runtime and writer.** An invariant test covers successful handoff, failed admission, interruption, failed stop, and repeated disposal. Keep package readers and transcript writers distinct but ordered.
2. **One decoder at each unknown-data boundary.** Derive data types from their schema; preserve authored public/substitution interfaces. Use the existing typed error vocabulary where it expresses recovery.
3. **One explicit SDK execution exception.** Main owns the composed application program; Pi-required Promise callbacks use an approved owner-bound adapter runner. The literal current skill forbids every such bridge, while existing code suppresses the rule. Update that policy alongside A07 and prove the exception's lifetime.
4. **Dependency rules follow chosen contracts.** Keep Pi imports confined to its adapter. Close implementation choices in composition. Ratchet real boundary violations after resolving the PiAgent specification conflict, not by introducing forwarding modules solely to appease a lint rule.
5. **Failure outcomes remain distinct.** Missing optional diagnostic data, unavailable Profiles, failed external operations, failed rollback, and defects must not collapse into the same empty value.
6. **Measure reduction by a change task.** Adding a model control, memory backend, or entrypoint should require editing its owner and relevant adapter/face, not a chain of identical signatures. Count those edits and lifecycle branches before/after. Do not promise arbitrary percentage/LOC savings.

Reject blanket rules that all files must be under 500 lines, every `_tag` comparison must disappear, every interface must be inferred, every top-level call is forbidden, or every `unknown` catch needs another error class. Pinned Effect itself uses tag comparisons and supports [`Semaphore.makeUnsafe`](/Users/yesh/code/personal/ziggy/vendor/effect/packages/effect/src/Semaphore.ts:152). Pure decoder construction and immutable embedded catalog validation differ from reading host state or starting live resources at import time.

The existing [composition plan](/Users/yesh/code/personal/ziggy/docs/plans/effect-composition.md) has already completed root wiring, host paths and exit handling. Retain that progress. Its remaining callback recipe needs lifetime ownership, and its proposed broad style bans should be narrowed before enforcement.

## Preserve these invariants

- Pi owns the loop, providers, tool execution and session JSONL. A new model registry, transcript database, or agent engine would duplicate authority.
- The Profile remains plain visible files. SOUL and other human-owned content are never replaced by cleanup work.
- Memory contexts distinguish shared, local-owner, person and group documents; group use does not read a member's private person file.
- Schema-derived data, typed expected failures, and plain total calculations already work well. Keep them.
- Extension selection, approved resources, required core resources, generation binding, optional quarantine and exact rollback are necessary policy, even where the code is lengthy.
- Session writer leases and package runtime leases protect different resources. A single generic lock is not automatically simpler.
- The registry's Opening/Live/Closing states, shared opens, scoped work and bounded replay prevent real races and preserve disconnect behavior. A bare Map would discard those guarantees.
- Prompt completion uses Pi's settled event and final transcript semantics. A simple wrapper around a prompt Promise is not a proven replacement.
- Read-only model/auth views, no-follow transcript reads, bounded naming, lineage references and automation receipts have concrete roles. Retain them.
- Existing UI session identities/pins and Slack/Discord behavior are compatibility constraints. Their implementation was not rewritten or live-tested here.
